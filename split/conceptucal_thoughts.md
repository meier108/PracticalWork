# Splitting data into training and test

Recent work uses the bottom 50% split. However, this split is not realistic because
no low fitness-score samples are part of the test set. Thus, we perform a cluster based 
split.

## Bottom 50% split

The bottom 50% refers to the samples with the lowest regression label values

This is a deliberate restriction used in offline model-based optimization (MBO) to 
simulate a realistic setting where:
* you only observe poor-to-moderate designs, and
* the algorithm must extrapolate toward high-fitness regions it has never seen.

Why this matters conceptually:
* It creates a distribution shift between training data and the true optimum.
* It prevents trivial memorization of high-scoring sequences.
* It tests whether a method can generalize and propose improved sequences, rather 
than interpolate.

## Cluster based split: Mimiking scenarios where base population stems from mulitple consensus sequence sampling

In realistic TF–DNA or protein–DNA settings, the initial dataset is not:
* all possible sequences (combinatorial space), nor
* a uniform random sample from that space.

Instead, it is typically generated by one (or more) of the following processes:

### (A) Local exploration around known binders
* Start from a known motif / consensus sequence
* Apply:
    - point mutations
    - small indels
    - position-specific randomization
* Result:
    - tight clusters in sequence space
    - strong local correlation between sequence similarity and fitness


### (B) Experimental or historical bias

* Sequences come from previous studies, known TF binding motifs, and curated databases.
* These are not random samples: they reflect what biologists already believe is relevant.
* Result: clustered, biased, incomplete coverage

### (C) Library-based screening (semi-random, but constrained)
* Examples: randomized positions at a subset of sites, fixed backbone + variable region, 
position weight matrix–guided libraries
* This gives: randomness within constraints clusters induced by shared backbone or fixed positions


### Resulting fitness landscape in A (also B, C)
Given such data, the observed population usually has:
* multiple clusters
* each cluster:
    - has high internal sequence similarity
    - spans a range of fitness values
* fitness varies smoothly within clusters
* sharp drops between clusters

## A realistic clustered training set:

### Step 1: pick a small number of seeds
Choose K “lead” sequences (consensus / motif-like). To avoid leakage from “already 
excellent” leads:
* sample seeds from a moderate fitness band (e.g., 60–80th percentile), not top performers
* if a candidate seed is too high (say > 90th percentile), reject and resample

This mimics “we have some sequences with somewhat okayish fitness, not the final answer”.

### Step 2: build clusters by local mutational neighborhoods
* Around each seed, sample sequences within a small Hamming radius:
* radius r ∈ {1,2,3} (or a distribution)
* sample n neighbors per seed

Result: K clusters with smooth local variation.

### Step 3: optionally add a small “background” set
Add a small number of random sequences (or weakly motif-biased sequences). This mimics 
assay baselines and helps calibration.

## Creating the test set
### Test A: near-generalization (within-cluster holdout)
Hold out some neighbors from the same seeds (same radius distribution) to test 
interpolation/local modeling.

### Test B: medium shift (further radius from seeds)
Hold out sequences at larger Hamming distance from the seeds than the training radius. 
Tests controlled extrapolation.

### Test C: novel-seed shift (different clusters)
Hold out entire seeds (and their neighborhoods). This tests generalization to new 
motifs/leads.

### Test D: global space (optional)
A uniform random set from the full space, just to characterize “global coverage”, but 
don’t let this dominate the headline metric.
